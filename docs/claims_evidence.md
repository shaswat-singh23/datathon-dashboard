# Claims & Evidence appendix

One row per claim that appears in the README or on a dashboard page. Each row names the table or query behind the number, the result, the alternative explanation that was tested, the main limitation, the `findings/` file that holds the full reproduction, and that file's `Checked by` line.

**Status gate.** Team rule (AGENTS.md, `findings/README.md`): a number goes into slides, the video or the write-up only from a finding whose `Checked by` is not `unchecked`. The last column copies that line verbatim at the time this appendix was last regenerated. Every row below is currently **unchecked**: all numbers were produced by code and reconciled by their authors against raw tables, and the merge-queue reviewer agent independently re-ran the Reproduce blocks of findings #23, #31, #32, #34 and #47 and matched their numbers, but no human has re-run any of them. Whether an agent re-run counts as a check is the decider's call. A reviewer who re-runs a finding's Reproduce block and gets the same numbers edits the finding's `Checked by` line in a PR and updates this column.

Conventions used throughout: Jan 1 to Jun 30 2025 unless stated; money math through `royale/money.py` (ratios are ratios of sums, theo = coin-in × (1 − configured RTP), luck = house win − theo); comparisons per available hour; 1,018 off-floor `machine_day` rows (`location_id` null) excluded from machine comparisons; location from `placements` at gaming-day start. Pages read only committed marts in `marts/`; the Reproduce blocks need the organizer data through `DATA_DIR`.
